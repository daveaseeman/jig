- `.jig/inbox/` (made by init, added by an update step), never committed; `jig inbox` in the
  trunk checkout prints unread messages oldest first and moves them to `read/`, sets a message
  for another repo aside in `misaddressed/`, and refuses in any other checkout; `jig inbox check`
  checks a header from outside any repo.
- The `UserPromptSubmit` hook `plugin/scripts/inbox.sh`: in the trunk checkout of a repo that
  opted in (`.git/jig/enabled`), it announces the unread count and `jig inbox`; it reads and
  moves nothing. `session-start.sh` counts unread messages.

- `jig repos alias`, `jig repos which`, every key of an entry kept, and one name rule
  (`repo_matches`): a listed name, alias or the checkout's own name, case ignored; a name more
  than one entry answers to finds none; a name matching only without punctuation is refused,
  naming the near one. `add`, `rename` and `alias` refuse a name another entry answers to.
  Staging (check, resolve, forward, the release wait) and the inbox use that one lookup.
- RULES.md `## Inbox` and the Commands lines; the hubnode skill's step 4; the repos skill; README.

## Test by hand
In a session outside a registered repo: `/jig:relay <repo> <a hubnode question>`, settle a reply,
`/jig:send`; the card shows the repo, the question and an editable reply; Fill reply, Enter; the
file lands in `<repo>/.jig/inbox/` and `inbox check` passes. Then a prompt in that repo's
hubnode session shows "jig: 1 unread message …", and `jig inbox` prints and marks it read.
